================================================================================
JVMXRay Agent — Log Sample Catalog
================================================================================

One sample per event type per relevant log level, for every shipped sensor.
Use this as a quick reference for what fields each event carries so you can
write parsers, dashboards, alerts, and SIEM rules.

LINE FORMAT
-----------
Every emitted event follows:

    CONFIG_FILE | timestamp | thread | priority | namespace |
    key1=value1|key2=value2|...

LogProxy automatically merges these fields into every event:

    caller        application stack frame that triggered the event
    AID           agent instance ID (from agent.properties)
    CID           configuration ID (from agent.properties)
    trace_id      MCC correlation ID, links nested sensor events
    scope_chain   nested sensor path (e.g., HTTP>SQL>FileIO)
    parent_scope  immediate parent scope, or "none" at root
    scope_depth   nesting level, integer as string

CAVEAT
------
Values are illustrative. AID, CID, timestamps, paths, hashes are
placeholders. Field presence varies — `error*` fields appear only on
failure; many fields are conditional on the runtime detecting the
relevant condition. Lines in this catalog are hard-wrapped at column
80 for readability; real log lines are emitted as a single physical
line.

DISABLED SENSORS
----------------
Reflection is the only fully-operational sensor that ships disabled by
default. It is commented out in agent.properties because of the overhead
of intercepting every reflective call; enable it per environment if
reflection-based attacks are in scope.

Two sensors — Memory and Thread — are wired but currently non-operational
due to unresolved recursive-logging issues; their loggers are removed
from the default logback.xml. Sample output for them is at the end of
this catalog under "Non-operational tbd".

17. UncaughtException  —  crash diagnostics for unhandled throwables
================================================================================
Namespace: org.jvmxray.events.system.uncaughtexception

Fires once per uncaught throwable on any thread. The sensor checks
which logger is enabled and emits the event at that level. INFO carries
the minimum useful diagnostic; DEBUG adds an extensive forensic dump
(cause chain, per-pool memory, GC stats, OS info, security state, disk,
detailed threads, system management info).

Note on stack_trace: the real sensor emits this value with each frame
on its own line. The samples below collapse frames into a single
` > `-separated string for documentation readability.
